# T.gemm

适用范围：Ascend 950，AscendC 后端，编译目标为 `target="ascend"`。使用 `from tilelang.ascend import language as T` 导入接口。

## OP 概述

`T.gemm` 计算两个矩阵的乘积，并将结果写入 L0C 中的 C。它可以从零开始计算，也可以在 C 的已有结果上继续累加。

- `clear_accum=True`：`C = op(A) × op(B)`。
- `clear_accum=False`：`C = C原值 + op(A) × op(B)`。

`op(A)`、`op(B)` 表示应用转置参数后的矩阵。M 是结果行数，N 是结果列数，K 是每个结果参与求和的长度；结果形状为 `[M,N]`。

支持两种输入位置：A、B 同时位于 L1；或者 A 位于 L0A、B 位于 L0B。L1 入口由内部完成 L1→L0 搬运，显式 L0 入口由调用方先搬入数据。计算后使用 `T.copy` 将 C 搬到 GM 或 UB。

## OP 规格

### 接口形式

```python
T.gemm(
    A,
    B,
    C,
    transpose_A=False,
    transpose_B=False,
    policy=GemmWarpPolicy.Square,
    clear_accum=False,
    unit_flag_ctrl=None,
    annotations=None,
)
```

### 参数说明

| 参数 | 含义 | 默认值和使用条件 |
| --- | --- | --- |
| A | 左侧输入矩阵，可以传缓冲区或矩阵选区。 | 必填。位于 L1 或 L0A，与 B 使用相同输入类型。 |
| B | 右侧输入矩阵，可以传缓冲区或矩阵选区。 | 必填。与 A 同走 L1 入口，或在 A 位于 L0A 时使用 L0B。 |
| C | 本次计算的结果及累加区域，逻辑形状为 `[M,N]`。 | 必填。位于 L0C，类型见数据类型支持表。 |
| transpose_A | 是否将 A 转置后参与计算。 | 默认 False；转置后的形状须与 B、C 匹配。 |
| transpose_B | 是否将 B 转置后参与计算。 | 默认 False；L1 入口必须显式设置为 True。 |
| policy | GEMM 策略参数。 | 默认且仅支持 `GemmWarpPolicy.Square`。 |
| clear_accum | 决定从零开始计算，还是保留 C 原值继续累加；可使用布尔值或可编译的布尔表达式。 | 默认 False。首次计算没有预先初始化 C 时，使用 True；后续累加段使用 False。 |
| unit_flag_ctrl | 控制计算和结果搬出的协同执行，使已经生成的部分结果可以开始搬出。 | 默认 None，等同于 0，表示关闭；2 用于连续操作的中间阶段，3 用于结束阶段。需要与对应结果搬出配套设置。 |
| annotations | 用字典设置附加执行配置。 | 默认 None。与独立参数配置同一项时，以字典中的值为准。 |

M、N、K 由矩阵形状、选区和转置参数确定。计算结果写入 C，再由调用方组织后续计算或搬出。

### 数据类型支持

表中 A、B 均使用同一种类型。“待确认”项不计入已确认支持范围。

| A、B 输入类型 | TileLang 类型名 | L1 入口 | L0 入口 | C 的累加类型 |
| --- | --- | --- | --- | --- |
| FP16 | `float16` | 支持 | 支持 | `float32` |
| BF16 | `bfloat16` | 支持 | 支持 | `float32` |
| FP32 | `float32` | 支持，可设置 HF32 | 支持，可设置 HF32 | `float32` |
| INT8 | `int8` | 支持 | 支持 | `int32` |
| FP8 E4M3 | `float8_e4m3fn` | 支持 | 支持 | `float32` |
| FP8 E5M2 | `float8_e5m2` | 当前未接入 | 待确认 | `float32` |
| FP4 E2M1 | `float4_e2m1fn` | 不支持作为普通 GEMM 输入 | 不支持作为普通 GEMM 输入 | — |
| A、B 使用不同类型 | — | 不支持 | 不支持 | — |

FP32 输入可通过 `T.set_hf32_mode` 设置计算模式；示例使用 `T.set_hf32_mode(None)` 关闭 HF32。

### 规格约束

#### 输入位置与转置

下面是传给 GEMM 的 A、B 形状，尚未应用转置参数。四种组合的结果形状都为 `[M,N]`。

| 组合 | transpose_A | transpose_B | A 传入形状 | B 传入形状 | L1 入口 | L0 入口 |
| --- | --- | --- | --- | --- | --- | --- |
| NN | False | False | `[M,K]` | `[K,N]` | 不支持直接调用 | 支持 |
| NT | False | True | `[M,K]` | `[N,K]` | 支持 | 支持 |
| TN | True | False | `[K,M]` | `[K,N]` | 不支持直接调用 | 支持 |
| TT | True | True | `[K,M]` | `[N,K]` | 不支持直接调用 | 支持 |

A、B 必须成对位于 L1，或分别位于 L0A、L0B。A 在 L1、B 在 L0B 等混合输入位置不作为支持用法。提前转置搬运数据后使用 L1 NT，可以实现对应的数学计算，调用时仍须满足 L1 的转置参数组合。

#### 尺寸、静态与运行时范围

以下尺寸条件须同时满足缓存容量、布局和搬运要求，各维最大值不能直接拼成一个计算组合。

| 项目 | 约束 |
| --- | --- |
| 单次 L1 GEMM 的 M、N | 必须为 16 的正整数倍，且不超过 4080；具体组合还须满足缓存容量限制。 |
| 单次 L1 GEMM 的 K | 必须是编译时确定的正整数，且能被 C0 整除。C0=256/b，b 为输入位宽。 |
| 单次 L1 GEMM 的尺寸确定时机 | M、N、K 均须在编译时确定。 |
| 单次 L0 GEMM 的有效 M、N、K | 均为正数，单次有效计算各维不超过 4095。有效尺寸可以不对齐，但存储空间和搬运范围必须满足对应类型的分形及对齐要求。 |
| L0 分配与有效范围 | 缓冲区分配大小必须在编译时确定；本次有效 M、N、K 可以使用运行时表达式指定，并满足尺寸、存储和搬运要求。 |
| 整张矩阵 | 通过外层分块和循环覆盖；单次计算的尺寸范围不作为整张矩阵的统一上限。 |
| 高维缓冲区 | 支持选取单个矩阵计算。一次调用处理一组矩阵，批量计算通过外层循环完成。 |
| 零尺寸 | 不在本规格范围内。 |
| 单行矩阵 | 未来支持。 |

L1 入口常用 K 对齐如下；这些条件针对单次 GEMM 的计算 K，整体矩阵的原始 K 可以通过尾块补齐处理。

| 输入类型 | C0，即 L1 计算 K 的对齐单位 |
| --- | --- |
| FP32 | 8 |
| FP16、BF16 | 16 |
| INT8、FP8 E4M3 | 32 |

#### 布局、选区与搬运

- 使用逻辑矩阵 shape 和索引；A、B、C 的 NZ/ZN 物理布局及转换由编译器后端处理，调用方按本页的形状和转置条件准备数据。
- 传给 GEMM 的 L0 A、B、C 区域均须从各自矩阵的 `[0,0]` 开始，可以选择从零开始的较小有效区域。
- 转置搬运须满足对应输入类型的对齐要求，需要时补齐存储空间和搬运范围。
- 支持分多次将数据搬入 L0 的不同位置。每次搬运满足分形对齐并使用匹配的 `l0_pitch`，最终计算区域从 `[0,0]` 开始。
- 搬运间隔须与最终计算区域匹配；裁剪结果搬出时，也须保持实际计算结果的间隔，需要时设置匹配的 `l0_pitch`。
- 更换转置方式时，输入形状和搬运方式需同时匹配新的计算方式。

#### D 维与 K 维尾块

M、N 统称 D 维。“有效尺寸”指真正需要计算的数据范围；补齐空间用于满足存储和搬运要求。

| 入口 | 有效 M=125 的处理方式 | 结果输出 |
| --- | --- | --- |
| L1 | 按 M=128 准备计算块，在 L1 中对额外行补零，按 128 行计算。 | 只输出前 125 行。 |
| L0 | 按要求准备存储和搬运范围，可直接指定有效 M=125；也可补零后按 M=128 计算。 | 输出有效 125 行，或将完整块结果裁剪为 125 行。 |

N 尾块同理：准备 B 对应的数据，输出所需的前 125 列。

| 入口 | 有效 K=125 的处理方式 |
| --- | --- |
| L1 | 125 不满足 C0 对齐要求。选择合法计算 K，例如 128，并在 L1 中将 A、B 额外的 3 个 K 位置置零。 |
| L0 | 可以按有效 K=125 计算，额外存储位置不参与求和；也可以补零后按合法完整 K 计算。 |

采用补零方案时，先在 L1 准备补零数据，再将包含补零部分的数据搬入 L0。仅扩大分配空间，不代表已经补零。K 是求和维度，额外乘积必须通过有效 K 或补零排除；输出裁剪只作用于 M、N。

#### 输出与 Fixpipe 随路转换

| 输出路径 | 支持范围 |
| --- | --- |
| L0C `float32` → GM | 支持 `float32` 同类型输出，以及 `float16`、`bfloat16` 随路类型转换。 |
| L0C `int32` → GM | 支持 `int32` 同类型输出。 |
| L0C `float32` → 单目的 UB | 支持输出为 `float16`、`bfloat16`；UB 行间隔与实际写入范围须满足 32B 条件。 |

目标缓冲区的类型决定输出类型。FP32→FP16/BF16 转换在 `T.copy` 搬出时完成，无需额外量化系数，C 的累加类型保持 FP32。

UB 是芯片上的临时缓冲区。相邻两行起点之间的间隔须为 32 字节的倍数，并预留补齐后的写入空间。例如 19 个 FP16/BF16 元素占 38B，每行至少预留 64B。单目的 UB 的后续处理和写回由接收方执行，可使用 `T.MixedKernel(..., sids=1)` 限定到向量核 0。

#### 连续计算与执行配置

- 首段没有预先初始化 C 时使用 `clear_accum=True`，后续段用 False 累加到同一个 C；开始新计算时重新清零。
- 较小 M/N，例如 M=N=16 或 32，连续累加的支持情况仍需按具体尺寸组合确认。
- 使用 `unit_flag_ctrl` 时，GEMM 与对应结果搬出配套设置；连续操作的中间阶段与结束阶段按参数说明区分。
- 开启协同执行并输出为普通二维矩阵时，使用 `T.set_mmad_direction("n")`。方向表示一次 GEMM 内部沿结果行或列生成结果块的顺序，`"n"` 为列方向 N 优先，不改变矩阵形状和转置含义。
- 当前接口没有 Bias 输入参数。

## 示例

以下两个设备函数计算有效的 `17×24` 与 `24×19` 矩阵乘法。B 按 `[N,K]` 存放，设置 `transpose_B=True`。可使用 `tilelang.compile(设备函数, target="ascend", out_idx=2)` 编译。

### L1 输入：补零计算后裁剪输出

```python
from tilelang.ascend import language as T


@T.prim_func
def gemm_l1(
    A: T.Tensor((17, 24), "float32"),
    B: T.Tensor((19, 24), "float32"),
    C: T.Tensor((17, 19), "float32"),
):
    with T.Kernel(1):
        a = T.alloc_l1((32, 32), "float32")
        b = T.alloc_l1((32, 32), "float32")
        acc = T.alloc_l0c((32, 32), "float32")
        T.set_hf32_mode(None)

        # 请求准备完整的 32×32 输入块。
        # 编译器只读 A/B 中实际存在的数据，在 L1 补零。
        T.copy(A[:32, :32], a)
        T.copy(B[:32, :32], b)

        # 输入来自 L1，TileLang 内部负责 L1→L0 的搬运。
        # 这里传完整缓冲区，计算 M=N=K=32。
        T.gemm(a, b, acc, transpose_B=True, clear_accum=True)

        # 只取实际需要的 17 行、19 列。
        T.copy(acc[:17, :19], C)
```

### L0 输入：显式搬运后只计算有效区域

```python
from tilelang.ascend import language as T


@T.prim_func
def gemm_l0(
    A: T.Tensor((17, 24), "float32"),
    B: T.Tensor((19, 24), "float32"),
    C: T.Tensor((17, 19), "float32"),
):
    with T.Kernel(1):
        a = T.alloc_l1((32, 32), "float32")
        b = T.alloc_l1((32, 32), "float32")
        a0 = T.alloc_l0a((32, 32), "float32")
        b0 = T.alloc_l0b((32, 32), "float32")
        acc = T.alloc_l0c((32, 32), "float32")
        T.set_hf32_mode(None)

        # 和上面一样，在准备 L1 输入时补零。
        T.copy(A[:32, :32], a)
        T.copy(B[:32, :32], b)

        # 调用方明确写出 L1→L0 的搬运。
        T.copy(a, a0)
        T.copy(b, b0)

        # 搬入了完整块，计算只使用指定的有效范围。
        T.gemm(a0[:17, :24], b0[:19, :24], acc[:17, :19], transpose_B=True, clear_accum=True)

        T.copy(acc[:17, :19], C)
```
