# GEMM 逐用例执行报告

本文件只记录本次实际执行结果。固定随机种子写在各测试文件；不锁定环境版本。

COMPILE_ONLY 表示设备编译通过但数值未验收；SKIP 表示必需条件缺失；均不计作真机数值通过。
SIMULATOR 表示仿真辅助验数，不能作为真机实测结果。
OBSERVED 表示调用方约束的编译防护观察，不是数值PASS，也不要求编译器承担调用方责任。

## 当前实现和验证边界

当前工作分支为 `gemmcheck`，修改基于已推送提交 `98f29987`。完整kernel仍在各测试文件中，119个kernel的AST未改变；53个CPU参考重排为本地 `make_inputs()` / `ref_program()`，输入、初值和参考的SHA256均与修改前一致。

- 81个完整DSL入口按 `example_gemm.py` 的方式，在本文件main中直接 `tilelang.compile`。53个数值入口将输出返回或初值克隆作为result，然后与本文件CPU参考对照，报告max_diff和正确性。
- `out_idx=-1`用于返回输出；`out_idx=None`用于传入初值或GM哨兵。保留INT32精确比较、FP4独立解包、scale逻辑解码、手动调度和重复启动次数。5个部分写回场景的GM外围哨兵单独以零容差精确检查。默认没有新增性能测量。
- 第一部分输出 `program.script()` 输入TIR、`kernel.get_kernel_source()` 的实际AscendC源码及设备IR；第二部分输出验收结果。
- 38个局部IR场景按pass边界验证；原IR文件增加对应输出，并新增T05-IR有效K96对齐负例。准确原节点命令见[IR测试命令](IR_TEST_COMMANDS.md)。

## 实际执行结果

主目录119项当前汇总：**64 PASS、1 OBSERVED、1 FAIL、53 SKIP**。53个数值main均完成真实JIT编译及源码/IR输出；由于本机没有可用NPU，没有执行kernel数值计算，未将历史仿真PASS计入当前main的真机结果。T08完成调用方范围观察；T05仍未被编译器拒绝。

首次全量pytest发现28个局部IR入口被误送入JIT；这是本次入口改写的问题，已修正。修正后38个IR入口独立重跑全部通过；其余81个完整DSL入口的全量执行证据保持不变。因此上面的119项汇总来自全量执行和受影响IR入口的复核，不声称修正后再次全量运行119项。

原两个IR测试文件的完整回归结果：**74 passed、1 failed**；唯一失败为新增T05-IR，实际下沉接受有效K96，而预期应拒绝。这与T05的直接JIT负例指向同一K对齐问题。未执行非法指令，也未使用xfail。

历史S12的uint8 scale数值偏差和O01仿真超时保留在[历史报告](TEST_REPORT.md)中。本轮没有NPU实测，不能据当前SKIP消除这些待真机复核项。
