# Ascend GEMM 逐用例执行指南

本目录基于 origin/main 重新整理，测试源码直接位于原仓库 testing 下。每个二级特性一个目录，每个测试文件只有一个测试单元、一个固定场景。

## main直接执行方式

81个完整DSL用例在各自 `main()` 中直接调用 `tilelang.compile`，53个数值用例随后直接执行kernel并调用本地 `ref_program()` 验证CPU参考。普通输出采用 `out_idx=-1` 和 `result = kernel(*inputs)`；需要初值或保留GM哨兵时采用 `out_idx=None`、`result = initial.clone()`，将result传入kernel。所有数值用例报告max_diff，并沿用各场景原有的atol/rtol；INT32和要求零误差的场景保持精确比较。

部分写回用例T01/T02/T14/T15/T43对GM外围哨兵另做零容差比较，不使用有效计算区的浮点容差放宽哨兵检查。

`program.script()`打印输入TIR；实际编译源码由 `kernel.get_kernel_source()` 打印；另打印设备IR。约束负例直接检查编译异常，接受非法输入时FAIL，不启动非法指令。

38个直接构造IR的局部场景保留pass单元测试入口。它们在原文件的参数节点以及新增T05-IR的具体命令见[原IR单元测试命令](IR_TEST_COMMANDS.md)。本次实际验证结果见[main直接执行版报告](DIRECT_MAIN_TEST_REPORT.md)。

## 开发人员直接执行

在已经安装当前仓库 TileLang、PyTorch/torch_npu、CANN 的终端进入仓库根目录。不固定机器、驱动或软件版本；数值测试需要设备支持对应的数据类型与指令。

```bash
# 一键完成全部真机数值、编译拦截和IR验收，并生成逐用例报告
python testing/ascend/gemm_features/run.py --report gemm-report.md

# 失败时才在指定目录保存完整复现材料；通过或跳过都不创建该目录
python testing/ascend/gemm_features/run.py --report gemm-report.md --failure-dir gemm-failures

# 指定设备，或只执行一个二级特性 / 一个单元
python testing/ascend/gemm_features/run.py --device 0 --group scaled_gemm --report scaled-report.md
python testing/ascend/gemm_features/run.py --case S03 --report s03-report.md

# 任意文件均可单独运行，不要求先执行其他单元
python testing/ascend/gemm_features/scaled_gemm/test_s01.py
python testing/ascend/gemm_features/scaled_gemm/test_s03.py --failure-dir gemm-failures

# 列出全部独立场景
python testing/ascend/gemm_features/run.py --list
```

也可采用仓库 testing 的 pytest 方式：

```bash
python -m pytest -q -s testing/ascend/gemm_features
python -m pytest -q -s testing/ascend/gemm_features/scaled_gemm/test_s03.py
python -m pytest -q -s testing/ascend/gemm_features --gemm-device=0 --gemm-failure-dir=gemm-failures
```

## 验收层级与返回值

- 数值单元：生成真实源码/IR、执行设备编译，再在真机与独立 CPU 参考逐元素比较。编译成功不能替代数值通过。
- 拦截单元：只改变一个非法条件；必须在前端、lowering 或设备编译中匹配目标诊断。其他原因失败仍算 FAIL；不会实际启动非法内核。
- IR 单元：S21、S26、T06、T07、T16–T41 共30项，只验指定 IR 结构，不要求真机，也不声称完成数值运行。
- 默认没有 NPU 的数值单元为 SKIP。`--mode compile` 只做到源码/IR和Bisheng编译，数值单元标 COMPILE_ONLY，在pytest中表现为跳过。
- T08是调用方范围约束的编译防护观察，结果为OBSERVED：如未拦截，明确调用方必须检查；不启动非法指令，也不当作数值功能失败或数值PASS。
- 单文件/一键入口退出码：0=选中目标验收通过或已完成调用方约束观察；1=至少一项FAIL；2=没有FAIL但存在SKIP/COMPILE_ONLY，完整数值验收未完成。
- 一键入口的真机/仿真数值单元使用独立子进程，某单元报错或超时后继续其余单元。每个单元自行构造输入和CPU参考，不读取其他单元的输出。

```bash
# 无NPU时检查编译约束；不报告数值通过
python testing/ascend/gemm_features/run.py --mode compile --report compile-report.md

# 可选CAModel辅助验数，不替代真机验收；需要npusim/patchelf及CANN仿真组件
python testing/ascend/gemm_features/run.py --mode simulator --report simulator-report.md
python testing/ascend/gemm_features/scaled_gemm/test_s12.py --mode simulator --failure-dir gemm-failures
```

## 固定数据与输出接口

所有数值单元在各自文件中写死 `SEED = 20261119`，不提供外部seed参数。输入在CPU构造；CPU参考只使用PyTorch和独立E2M1/E8M0解码，不调用待测编译器。

第一部分向终端输出生成源码、输入IR和下沉IR；第二部分输出验收状态。仅数值实际比较通过时报告“运行结果正确”。前端已拒绝的调用没有后续设备源码；IR局部单元没有独立GM入口，明确说明不生成可运行AscendC源码。

默认不创建日志、张量、源码或IR文件。`--failure-dir PATH` 是唯一失败材料输出接口，只在FAIL时创建 `PATH/<用例ID>/`，包含测试文件、相关构造源码、已生成的IR/AscendC、CPU输入/参考、可获得的实际输出和错误日志。预期拒绝并匹配诊断属于PASS，因此不写失败材料。临时设备编译/仿真文件在临时目录中执行并清理。

`--report PATH.md` 是显式报告输出接口，与失败日志分开。成功用例不生成复现包；测试报告始终每个选中单元单独一条。

scale的CPU参考使用逻辑E8M0字节值：每K32重复一个 `2**(byte-127)`。uint16是相邻两字节的存储打包，不能将uint16整数直接代入缩放公式。FP4按独立E2M1 nibble查表解码。

## 约束责任

| 责任 | 验证方式 |
| --- | --- |
| 前端/下沉编译器：形状、零起点、scope、SF绑定/槽/K覆盖等 | 对单个非法条件检查实际诊断，接受非法输入或报无关错误均FAIL |
| 设备编译器：M/N的16对齐、MAD可用类型组合等 | 必须执行Bisheng，单看IR无法证明拦截；类型负例关闭GM写回，排除Fixpipe错误干扰 |
| 调用方：scale值装入对应数据槽、匹配布局、首轮初始化、合法运行时范围 | 用合法设置进行CPU/设备数值对照；不宣称编译器会检查槽内数值或任意运行时越界 |
| 调用方：INT32数值不溢出 | CPU用INT64计算并验证范围后转INT32；不要求编译器根据运行时值静态拦截溢出 |

明确由编译器负责的约束未拦截按FAIL保留，不使用xfail；调用方负责的范围合法性单列OBSERVED，保留当前是否提供静态防护的观察。不以本次编译器行为反向修改其应负责的验收预期。
