# GEMM 逐用例执行报告

本文件保留提交 `98f29987` 对应的历史仿真与约束证据。按example_gemm.py改写main后的当前执行结果见[main直接执行版报告](DIRECT_MAIN_TEST_REPORT.md)；原IR入口及新增K96负例的精确命令见[IR测试命令](IR_TEST_COMMANDS.md)。下表的历史仿真通过不代表改写后的main已在真机执行。

本报告汇总同一任务的实际执行证据，逐行区分本轮执行与源码/CPU哈希一致的前轮仿真复用。固定随机种子写在各测试文件；不锁定环境版本。

COMPILE_ONLY 表示设备编译通过但数值未验收；SKIP 表示必需条件缺失；均不计作真机数值通过。
SIMULATOR 表示仿真辅助验数，不能作为真机实测结果。
OBSERVED 表示调用方约束的编译防护观察，不是数值PASS，也不要求编译器承担调用方责任。

## 交付与执行结果

源码直接位于原仓库 `testing/ascend/gemm_features`，开发与发布分支为 `gemmcheck`，远端为 `fork`（`zcccc03/tilelangfork`），基于本地 `origin/main`（`562cbc7c8188d4521920e76b708d00168e778f3b`）。本次测试整理未修改编译器实现。

- 119个文件、119个独立单元，覆盖14个三级特性；目录为scaled_gemm 29项、data_types 30项、tails 43项、semantics 17项。
- 每个文件均有完整本地kernel，53个数值文件有各自CPU参考；不依赖公共kernel/CPU工厂。内核来源和固定输入输出契约逐单元写在文件头及执行指南。
- 汇总验收为 **115 PASS、3 FAIL、1 OBSERVED**。其中51项完成CAModel/CPU数值对照，64项完成IR或预期拒绝验收；T08为调用方约束观察。
- 本轮全量默认pytest：**65 passed、1 failed、53 skipped**。唯一失败为T05；53项数值单元因没有物理NPU跳过。pytest的65 passed包含T08的观察完成，不代表65项数值通过。
- 当前无物理NPU，本报告没有真机数值实测结论。数值最终验收必须在支持对应指令/数据类型的昇腾NPU运行；不限定固定机器或软件版本。

## 证据来源与复用边界

1. 本轮对119个最终本地kernel单元执行了默认pytest，完成全部IR、前端与Bisheng约束检查；数值单元生成源码/IR并完成设备编译后明确SKIP。
2. 对内联前已有的45个数值单元比较生成C++源码和CPU输入/参考的SHA256：39项完全一致，6项采用原仓库kernel重新复制后发生变化。
3. 39项哈希一致的前轮仿真证据按行明确注明复用；其中S12另在本轮重跑。其余6项改写和8项新增数值单元全部重新仿真。因此本轮独立执行了15个数值单元（包含S12），随后S27单独复核通过。
4. S27首轮暴露的是仿真设施处理uint16单列张量stride的导出错误；改为展平后导出字节，再单文件运行，结果与CPU误差0。该设施错误已修复，不计入特性失败。
5. 11项直接构造IR的本地化内核另行复核全部通过（包含合法IR与预期拒绝）；26项MX padding IR断言及1项物理K拒绝检查也在119项全量执行中通过。纯IR验收共30项。每个文件均只有一个pytest入口，固定seed=20261119，无跨单元数据依赖。
6. 默认只向终端输出源码/IR和运行结果。失败材料只在指定 `--failure-dir` 且FAIL时保存；报告由显式 `--report` 接口输出。O01的旧超时证据保留，未将其伪装成新执行结果。

最终交付检查：119个文件均通过完整本地kernel/单一pytest入口/文件头契约审查；53个CPU参考共200个张量可正确导出字节。S26与T42通过一键入口；S10从仓库外工作目录独立完成源码/IR及设备编译，按约定返回COMPILE_ONLY/退出码2。显式日志接口复核中，S03预期拒绝PASS不创建材料，T05实际FAIL保存与原文件完全一致的本地源码、IR及错误日志，一键入口返回1。128个Python文件通过Ruff检查和格式检查。
